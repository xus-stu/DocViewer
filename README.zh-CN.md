# DocViewer

RTF / TXT / Markdown 多文件阅读器，纯前端实现，不需要联网，也不需要安装任何依赖。

前端是 HTML + CSS + JavaScript，直接用浏览器打开 `index.html` 就能用。另外附带一个
Swift 写的 macOS 外壳，把它包成普通的 `.app`：有原生窗口、原生文件选择器，并且能把编辑
写回源文件。

仓库里没有打包工具，没有 `node_modules`，没有第三方运行时库。

## 快速开始

```bash
open index.html                   # 或者直接双击；也可以用 ./run.sh
./packaging/mac/build_native.sh   # 打包成 macOS 应用（默认输出到桌面）
```

编译原生应用需要 macOS 与 Command Line Tools（`swiftc`）。只有重新生成图标才需要 Python 3 和 Pillow。

## 功能

### 文件与浏览

- 支持 `.rtf` / `.txt` / `.md`，以及常见源码与配置文件（`.java` `.kt` `.py` `.js` `.ts`
  `.go` `.rs` `.c` `.cpp` `.cs` `.swift` `.rb` `.php` `.sh` `.sql` `.html` `.css`
  `.json` `.xml` `.yml` `.toml` `.gradle` `.properties` 等），源码按纯文本视图显示
- 还能**只读预览**图片（PNG / JPEG / GIF / WebP / TIFF / BMP / HEIC / SVG）、PDF、Word
  （`.docx` / `.doc`）与 Pages（`.pages`）：这几类没有编辑与写回，只负责看清楚
- 「打开文件」可多选，「导入文件夹」递归读取目录，也可以把文件或整个文件夹拖进窗口
  （`.pages` 这类目录形式的文件包按一个文档收下，不会列出里面的内部数据文件）
- 侧栏列出文件，带类型图标、大小、类型标签、悬停删除按钮与文件名筛选。选中、切换、
  上下键移动都在原地改类名，不重建列表
- 侧栏可以单独收起（顶部 `‹` 按钮、`⌘B` 或设置面板），收起时留一个展开把手，状态会记住
- 会话记忆：重新打开时恢复上次的文件列表与正文，也可以记住每个文件的阅读位置

### 文件拼接

把多个文件按顺序合成一个阅读视图，用于对照或串读。原文件不受影响。

1. 在侧栏选中两个以上文件，可以用 `Ctrl/⌘` 点选、`Shift` 连选，拖动行调整顺序
2. 点选择条上的「拼接到一起」或按 `⌘M`
3. 生成一个拼接条目，原来的文件条目从列表里收起，磁盘上的文件没有任何改动

拼接视图支持分段标题、段间跳转（`Alt+←` / `Alt+→`）、复制合并文本、导出 HTML，
以及「拆开」还原成原来的文件条目。拼接可以嵌套，也可以混合 MD / TXT / RTF。

拼接条目持有原文件条目的引用，渲染时按段拼出 HTML，不复制正文，也不写回磁盘。
会话会把各来源一起保存，所以重新打开后仍是合并视图，拆分与分段标题都还能用。

### 格式与编码

| 格式 | 处理方式 |
|------|----------|
| `.md` | 自带 Markdown 渲染器：标题、列表与任务列表、表格、引用、代码块（含语言高亮）、链接、图片、分割线、目录 |
| `.rtf` | 自带 RTF 解析器：字体表与颜色表、粗体/斜体/下划线/删除线、上下标、字号、前景与背景色、段落对齐缩进、`\par` `\line` `\tab`、列表、简单表格、`\'hh` 与 `\uN` 转义 |
| 图片 | 按窗口宽度缩放显示，点一下在「适应窗口」与「原始大小」之间切换；标题下显示像素尺寸 |
| `.pdf` | 原生 PDFKit 逐页渲染成位图，滚到哪渲染到哪，只缓存最近十几页 |
| `.docx` / `.doc` | 页面里自己解 ZIP、解析 `word/document.xml`：标题、段落、粗体/斜体/下划线/删除线、颜色、对齐、列表、表格、上下标，以及**内嵌图片**（关系表 + media → data URL，按 EMU 还原尺寸）；`.doc` 与解析失败时退回系统 Quick Look 预览图。默认统一用阅读器的字体与字号（标题层级保留），可以在设置里关掉以还原文档本身排版 |
| `.pages` | 交给系统 Quick Look 画第一页（新版 Pages 也是目录形式的文件包）；Quick Look 不行时再找文件里自带的 `preview.jpg` |
| 其它 | 等宽字体纯文本视图 |

图片、PDF、Word、Pages 是**只读预览**：没有光标、不参与搜索、不参与拼接，也不会写回原文件。

编码检测按 BOM、严格 UTF-8、GB18030/GBK、Big5、Windows-1252 的顺序逐级尝试，
全部失败时用非致命 UTF-8 打开，保证任何文件都有内容显示，而不是直接报错。

RTF 里的 `\'hh` 字节按文件声明的代码页解码：

- `\ansicpg936` 按 GBK 解，950 按 Big5，932 按 Shift-JIS，1252 按 CP1252
- 没有 `\ansicpg` 时看字体表的 `\fcharset`：134 视为 GBK，136 视为 Big5，0/1/2 视为 1252
- 都没有才默认按 936 处理
- 声明为多字节编码时，不能构成合法序列的字节会被丢弃，不会改用 CP1252 解释。
  否则 cp936 文件里的一个孤立 `\'97` 会变成破折号混进中文正文

连续出现的 `\'hh` 会先收集成字节序列再整段解码，因为 GBK / Big5 是多字节编码，
逐字节解码只会得到 U+FFFD。

### 编辑（默认关闭）

默认是只读模式：正文没有光标，不会改动任何文件。切换到「可编辑」后，光标可以放到正文
任意位置直接修改，停手约 1.5 分钟后自动写回源文件，也可以随时点工具栏的「保存」立即写回。首次写入会先留一份 `.bak`。

- RTF：按所见即所得编辑，写回时重新序列化正文，文件开头的字体表、颜色表与样式表原样保留，
  正文沿用文件自己的 `\fN` / `\fsN`。中文写成 `\uN` 转义，并**沿用源文件的 `\ucN`**：
  源文件是 `\uc0`（转义后面不跟替代字符）就还是 `\uc0`，是 `\uc1` 才补一个 `?`。
  真段落写成 `\par`，只有源文件里的软换行才写 `\line`；空段落也会保留
- 文本与源码：按纯文本编辑，写回时使用文件原本的编码
- Markdown：不参与编辑，始终保持渲染后的显示

设置存在 `localStorage`，面板里有「恢复默认」。视觉设置都写成 CSS 自定义属性与
`body[data-*]`，所以主题、字体、颜色可以自由组合，切换时不会重建文档。

「记住每个文件的阅读位置」默认开启：重新打开文件或重启应用都会回到上次读到的位置，只读模式也一样。
写回源文件时不会再重绘正文，所以滚动位置与光标都不会被挪动。关掉则每次从顶部开始。

### 沉浸式阅读

隐藏标题栏、侧栏、工具栏与状态栏，只留正文，并加大上下留白。移动鼠标会唤出底部控制条
（进度、上下文件、字号、退出），2.2 秒无操作后淡出。点控制条上的「退出沉浸」或用工具栏的「沉浸」按钮返回。

### F3 调试面板

按 `F3`（或 `⌘D`、`F12`）打开右侧抽屉，分四页：

| 页 | 内容 |
|----|------|
| 性能 | 渲染帧率曲线、显示器刷新率、平均帧间隔、最差帧、掉帧计数、调度吞吐探针、渲染耗时、DOM 节点数、JS 堆占用、页面存活时长 |
| 文档 | 文件名、路径、类型、字节数、编码、行数、字符数、解析与注入耗时、视图模式、字号与换行状态、解析告警 |
| 环境 | User-Agent、语言、平台、CPU 线程、窗口与屏幕尺寸、DPR、色深、各 Web API 支持情况、GBK 解码能力、启动与就绪耗时 |
| 日志 | 带时间戳的分级日志，可自动滚动、复制、清空 |

关于帧率：`requestAnimationFrame` 与显示器刷新率绑定，60Hz 屏幕上只能得到 60fps，
所以动画循环改用 `setTimeout(1000/cap)` 驱动，`requestAnimationFrame` 只用来采样实际
显示帧率。120 / 180 / 240 的档位真的会按该间隔运行，屏幕上仍然是每秒约 60 张画面，
收益在于缓动与滚动的时间步进更细。实测 60fps 与 240fps 的 CPU 占用分别为 7.9% 与 8.1%。

## 快捷键

只有一个：

| 按键 | 功能 |
|------|------|
| `F3` | 打开或关闭调试面板 |

其余功能都做成了界面按钮（工具栏、侧栏顶部、设置面板），这样在正文里打字不会误触发操作。
之前的无修饰键（`N` 切换文件等）已经去掉：在正文里打一个 `n` 就跳到别的文件，实在是太容易误触。

## 实现说明

- 窗口默认取屏幕的 75% 并居中，不使用 `setFrameAutosaveName`，避免上次的位置覆盖默认值
- 首次打开且没有本地数据时载入 `README(EN).md` 与 `README(ZH).md` 两份内置说明
- 原生外壳注册 `docviewer://` scheme 并通过 `WKURLSchemeHandler` 读取包内资源，
  响应带 `Cache-Control: no-store`，启动时另外清一次 WebKit 缓存，避免改了 CSS / JS 却看不到效果
- 拼接条目只持有引用，不深拷贝正文；选中与勾选只改类名，不重建列表，因此没有多余的入场动画
- RTF 解析器按样式签名变化切分文本 run，`\pntext` 只写内部标记，真正建立 `<ul><li>` 放在文本落盘时
- RTF 换行：实际文件里 `\par` 常常为 0，换行只有编辑器硬折行与裸 `\n` 两种形态。
  默认把每个源文件换行输出为 `<br>`，设置里可以用「RTF 按源文件换行」切回严格行为
- RTF 颜色表的第一项是空的，表示自动色。解析器把空项存为 `null` 而不输出颜色，
  正文因此跟随阅读器配色；对比度过低（低于 3:1）的颜色也会回退为阅读器配色
- Markdown 列表先解析成树再渲染，避免字符串后处理产生非法嵌套

## 写回的安全边界

编辑写回只改正文，但下面这些情况会被**阻止**或保护起来：

| 情况 | 行为 |
|------|------|
| 文件含图片 / 页眉页脚 / 脚注 / 域（解析时被跳过、不在 DOM 里） | **默认阻止写回**并说明会丢什么；也可以选「仍然保存（会丢内容）」自己担着 |
| 内容为空而原文件非空 | 原生侧**拒绝写入**（防止把文件截成 0 字节） |
| 备份写不出来（权限不足、`.bak` 被同名目录占用） | **中止写入**，不做无备份覆盖 |
| 非 UTF-8 文件（GBK / Big5 / UTF-16 / cp1252） | 按**原编码**写回；编码名认不出来时报错，不再静默落成 UTF-8 |
| RTF 前言里的原始字节 | 按 latin1 原样写回，不会把 `\ansicpg936` 的文件重编码成 UTF-8 |
| 目标路径是软链 | 先解析到真实路径，不会把软链替换成普通文件 |
| 文件在打开之后被别的程序改过 | 检查磁盘内容哈希，改动过就不盲目覆盖，弹出「重新加载磁盘版本 / 取消 / 仍然覆盖」三选一 |
| UTF-8 / UTF-16 的 BOM | 写回时保留，第一次保存不会把 BOM 抹掉 |
| 有硬链接的文件 | 改成原地覆写，所有链接名都能看到新内容（不再换掉 inode） |
| 带扩展属性（如 `kMDItemWhereFroms`）的文件 | 原子替换后把扩展属性带过去 |
| 有未落盘的改动时重绘 / 关文件 / 清空列表 / 复位 / 关窗口 | 先把改动写出去，再重绘 / 关闭 |

备份两份：`.bak` 是**首次写入前的原始版本**（只写一次，不再覆盖），`.bak.prev` 是每次写入前的上一版（滚动更新）。

## 已知限制

- RTF 只覆盖 TextEdit / WordPad / Word 常见的子集，域、脚注、页眉页脚、内嵌图片与修订标记会被跳过
- RTF 表格只做基础的行列还原，不解析边框样式与合并单元格
- Markdown 渲染器刻意做得很小，不解析引用式链接定义与数学公式
- Word 预览不显示脚注、页眉页脚与修订标记；表格只还原行列与合并列；图片只认 PNG / JPEG / GIF / BMP / WebP / TIFF / SVG，Word 里的 EMF/WMF 矢量图会被跳过
- Word 文档里「跟随主题」的文字颜色（`w:themeColor`）会被忽略；其它颜色如果与阅读背景对比度低于 3:1，也会改用阅读器配色，免得深色主题下看不见
- Pages 预览是系统生成的整页位图，文字不可选中（Pages 的正文是 protobuf，没法直接解析）
- Word 解析要用浏览器的 `DecompressionStream`（macOS 13.3+）；老系统上自动退回 Quick Look 预览图
- 会话记忆单文件上限 8 MB、总量 64 MB，超出部分只保留在内存中（只有「记住会话」用得到，
  打开与编辑不受影响）。导入文件本身没有数量与大小限制
- macOS 应用是 ad-hoc 签名，首次启动 Gatekeeper 会提示，右键打开或用
  `xattr -dr com.apple.quarantine` 解除
